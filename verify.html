How your key is checked

No black box: the panel reads its license database over plain HTTPS REST and returns one of four verdicts. This page documents the exact request and runs it live against production.

01

The exact request

CHECKLICENSEINFIREBASE(KEY) // DECOMPILED FROM PRODUCTION BUILD
// one HTTPS call, per key, at login:
GET https://kurama-mods-pro-default-rtdb.firebaseio.com/license_keys/<KEY>.json
     ?key=AIzaSyDcPbyCSJGwY3-WrICK2swoqRArbsihMEA

// connect timeout 5000ms · read timeout 5000ms

Your key becomes the database path. Whatever JSON lives at that node is the whole verdict.

02

Decision ladder

response == "null" or empty bodyINVALID
blocked == trueBLOCKED
expiresAt > 0 && expiresAt < now (epoch ms)EXPIRED
node present, not blocked, not expiredOK → loadMainUI()
network error / locked rules / HTTP 401+ERROR

On OK the app stores the key locally, re-fetches expiry via fetchUserKeyExpiryFirebase, then loads the panel.

03

Kill-switch

FIELD IN project_statusEFFECT (polled every 30s)
enabled : falseGlobal block dialog with message + link shown to every session
expiresAt < nowTreated exactly like enabled=false
message / linkOperator text and action rendered inside that dialog

A perfectly valid key still locks when the operator flips this switch — it is the master override above individual keys.

04

From the source

VERDICT LOGIC // JADX DECOMPILE OF PRODUCTION DEX
String body = read(conn.getInputStream());   // GET shown above
if (body.equals("null") || body.isEmpty())       return "INVALID";
JSONObject o = new JSONObject(body);
if (o.optBoolean("blocked", false))             return "BLOCKED";
long exp = o.optLong("expiresAt", 0);
if (exp > 0 && exp < System.currentTimeMillis()) return "EXPIRED";
return "OK";                                  // any exception -> "ERROR"

Shipped dex strings are XOR-obfuscated via per-class short tables, m(i,j,k)=table[i]^k; these are the decoded constants.
